# SIH-26104 Backend Development Guidelines

This skill defines the technical architecture, safety rules, coding standards, and procedures for maintaining and extending the FastAPI backend service of the SIH-26104 Voice Cloning Detection Platform.

## Backend Technology Stack

- **Runtime & Framework**: Python 3.11, FastAPI (>=0.111.0), Uvicorn (ASGI)
- **Data Validation & Settings**: Pydantic v2, `pydantic-settings`
- **Database & ORM**: PostgreSQL (application database) with SQLAlchemy 2.0 (Async Engine & AsyncSession), Alembic for migrations; in-memory SQLite/aiosqlite is used by test fixtures where applicable.
- **Audio & ML Pipeline**: NumPy, SciPy, Librosa, SoundFile, scikit-learn, PyTorch
- **Testing**: Pytest, `pytest-asyncio`, HTTPX (`ASGITransport`), in-memory SQLite test fixtures

## Application Structure & Layer Responsibilities

```text
backend/app/
├── main.py               # Application factory, lifespan management, CORS, root route
├── config.py             # Settings configuration with Pydantic BaseSettings
├── database.py           # Async SQLAlchemy engine, AsyncSessionLocal, get_db dependency
├── api/
│   └── v1/
│       ├── router.py     # Aggregates v1 sub-routers
│       └── endpoints/    # Route controllers (detections.py, health.py)
├── models/               # SQLAlchemy ORM declarative models (detection.py)
├── schemas/              # Pydantic request, response, and DTO schemas (detection.py, health.py)
├── services/             # Business logic & external systems
│   ├── audio_validator.py # File type, magic byte, size, and duration validation
│   ├── storage.py        # Secure local audio file storage
│   └── detection/        # Pluggable detection engines (base, mock, baseline, factory)
└── ml/                   # Machine learning feature extraction, classification, and inference
```

## Core Backend Development Rules

### 1. Route & Controller Design
- Mount new endpoints inside `app/api/v1/endpoints/` and register them in `app/api/v1/router.py`.
- Keep route handlers thin: handle request parsing, dependency injection (`Depends(get_db)`), invoke appropriate service layer classes, and return typed Pydantic responses.
- Explicitly declare `response_model`, `status_code`, and descriptive endpoint docstrings for automatic OpenAPI (`/docs`) generation.

### 2. Schemas & Contract Synchronization
- Define all input, output, and DTO structures in `app/schemas/`.
- Use `ConfigDict(from_attributes=True)` on response models returning SQLAlchemy entities.
- Ensure all enumeration definitions (including `PredictionEnum` and `RiskLevelEnum`) and response schemas in `app/schemas/detection.py` remain strictly synchronized with frontend TypeScript types (`frontend/src/lib/types.ts`).

### 3. Database & Async Transactions
- Always inject database sessions using `db: AsyncSession = Depends(get_db)`.
- Use SQLAlchemy 2.0 style queries (`select()`, `where()`, `order_by()`).
- Use `selectinload` for eager-loading relationships (e.g., `DetectionCase.result`) to avoid N+1 query overhead in async sessions.
- Keep models in `app/models/` inheriting from `Base` in `app/database.py`. When making schema changes, create an Alembic migration in `alembic/versions/`.

### 4. Service Layer & ML Inference Integration
- Isolate business logic from FastAPI HTTP concerns inside `app/services/`.
- To add or modify detection engines:
  1. Implement the `BaseDetectionService` interface defined in `app/services/detection/base.py`.
  2. Register the engine in `app/services/detection/factory.py`.
  3. Ensure it outputs a standard `DetectionResultDTO`.
- Do not run heavy blocking CPU tasks directly inside async route handlers; delegate compute to services or run via threadpools/background tasks when necessary.

### 5. Secure Audio Handling & File Safety
- Never trust client-supplied filenames directly. Always pass files through `AudioValidator.validate_filename_extension()` and `AudioValidator.validate_file_content()`.
- Enforce size limits via `settings.MAX_FILE_SIZE_BYTES` (default 25 MB).
- Verify magic bytes / signatures for audio files before storage.
- Store files using unique UUIDs generated by `AudioStorageService` to prevent path traversal and file collisions.

### 6. Configuration & Environment Variables
- Manage all configuration variables through `app/config.py` using `Settings`.
- Do not access `os.environ` directly in business logic.
- Update `backend/.env.example` when introducing new environment variables.

### 7. Authentication & Authorization (When Applicable)
- Currently, analysis endpoints are public forensics utilities.
- If user accounts, API keys, or admin roles are added, implement them as reusable FastAPI dependencies (`Depends(get_current_user)`) without breaking existing unauthenticated endpoints unless specified.

## Testing & Quality Verification

Always verify backend changes before completing tasks:

1. **Run Full Test Suite**:
   ```bash
   cd backend && pytest
   ```
2. **Run Specific Tests**:
   ```bash
   cd backend && pytest tests/test_detections.py tests/test_health.py
   cd backend && pytest tests/test_ml_baseline.py
   ```
3. **Database Migration Check**:
   ```bash
   cd backend && alembic check
   ```
